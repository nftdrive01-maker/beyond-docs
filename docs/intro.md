# BEYONDとは

**BEYONDは、特定のサービスやサーバーへの依存を前提としない、自律分散型の情報通信インフラを利用するためのアプリケーションです。**

ブロックチェーンをデータの記録・取得・配信・検証の基盤として活用し、利用者自身が情報を扱える環境を提供します。その中心となるVerified Browserでは、記録されたデータ実体だけでなく、トランザクション、ブロック、ネットワーク、取得元との関係を確認できます。

BEYONDが目指すのは、特定の事業者が提供するサービスを信頼するだけではなく、利用者自身が情報を取得し、その根拠を検証できる環境です。これはサーバーや運用者が不要になるという意味ではありません。データ実体と履歴を保持するノードやアーカイブ、利用できる取得経路を維持する必要があります。

Webサイトの公開、文書や動画の保存、業務記録の管理などは、この情報基盤の活用例です。BEYONDにはインストール不要のWeb版とWindowsデスクトップ版があり、目的に応じて利用できます。

- 初めての方：登録や鍵の作成をせず、Web版で [5分で体験するBEYOND](./guide/quickstart.md)
- Windows版を導入する方：[ダウンロードとインストール](./guide/installation.mdx)
- 技術思想を理解したい方：[特定のサービスに依存しない情報通信インフラ](./concepts/independent-infrastructure.md)

## 何のためのプロダクトか

BEYONDが実現しようとしているのは、**Don't Trust, Verify.（信頼するな、検証せよ）** という姿勢を、データの閲覧と利用に取り入れることです。BEYOND自身を無条件に信頼することを求めず、表示された情報の取得元と検証根拠を、利用者自身が確認できる状態を目指します。

この姿勢は、サトシ・ナカモトが [Bitcoinのホワイトペーパー](https://bitcoin.org/bitcoin.pdf) で示した、第三者への信頼に代えて暗号学的な証明に基づく取引を可能にする考え方や、Ethereumの共同創設者ヴィタリック・ブテリンが [Trust Models](https://vitalik.eth.link/general/2020/08/20/trust.html) で論じる、特定の主体への信頼依存を減らす考え方と共通する方向を目指しています。

BEYONDでは、その思想をデータ実体・トランザクション・ブロック・ネットワーク・取得元の関係をたどる仕組みに反映します。検証にはソフトウェアやネットワークなどの前提もあるため、何を確認でき、何に依存しているかを明確にします。詳しくは [BEYONDの信頼モデル](./concepts/trust-model.md) を参照してください。

ブロックチェーンには、日々多くのデータが記録されています。しかし、「記録されている」ことと、「データ実体や対象ネットワークとの対応を後から確認できる」ことは同じではありません。

BEYONDは、次のような問いに人間が答えられるようにするためのプロダクトです。

- このデータ実体は、対象チェーンの記録から取得・復元できるか
- どのブロック、どのトランザクションに記録されているのか
- どのネットワークの、どのノードから取得した情報なのか
- その検証は、どのような根拠に基づいているのか

## 保存だけで終わらせない、検証ブラウザ

BEYONDは、ブロックチェーンへのデータ書き込みと、記録されたデータの検証を一つの環境で扱うためのプロダクトです。

重要なのは、データを書き込むこと自体ではなく、保存されたデータについて**データ実体・ブロック・トランザクション・ネットワーク情報・検証根拠**を、人間が後から確認できることです。

保存は、データまたは記録を永続的な媒体へ配置する行為です。

保存された情報を取得し、ハッシュや参照関係などを照合したうえで、その結果と検証根拠から記録の状態を判断するのが検証です。

BEYONDは、**保存 → 取得 → 照合 → 検証**を一つの流れとして扱い、ブロックチェーン上の記録を**人間が検証可能なデータ**として利用できるようにします。チェーンへの書き込みは、保存するデータをトランザクションとして送信する操作です。

## 現在の主な機能

| 分類 | 主な機能と役割 |
| --- | --- |
| 閲覧・検証 | [Verified Browser](./guide/verify-data.md)で記録を検索・復元し、トランザクション、ブロック、ネットワークとの関係を確認する。[BeaconとAnchor](./advanced/beacon.md)でノードの署名付き宣言と別チェーンに記録した根拠を関連付ける |
| 作成・書き込み | [Studio](./guide/write-data.md)でファイルや文書・フォームを作成・記録し、[Jobs](./guide/jobs.md)で書き込み処理の進捗を確認する |
| ネットワークの設計・管理 | [Blockchains](./guide/network-profile.md)でネットワークとノードを管理する。[Designer](./guide/network-design.md)で独自ネットワークの構成・容量を計画し、概算や仕様書を作成する |
| 暗号化・鍵管理 | デスクトップ版の[ファイル暗号化とVault](./guide/file-encryption.md)でファイル暗号化キーと復旧フレーズを管理する。Vaultはアカウントの署名用秘密鍵を復旧する機能ではない |
| データの活用 | [ネームスペース](./guide/web5-site.md)でアドレスに名前を割り当てる。[Verified Drive](./guide/verified-drive.md)でWindowsへファイルを同期し、ローカル変更を検知する。Mosaicトレーサビリティでアセットの移転履歴を確認する |

機能差は [デスクトップ版とWeb版](./guide/editions.md) を参照してください。

## データ実体・ブロック・トランザクションを確認する意味

ハッシュ値だけが残っていても、元のデータ実体が失われていれば、記録の中身を確かめることはできません。

逆に、データ実体があっても、それがどのブロック・どのトランザクションに紐付いているかを確認できなければ、「いつ・どこに記録されたか」の根拠は曖昧になります。

BEYONDでは、次の要素をそれぞれ確認できます。

| 確認対象 | 確認できること |
| --- | --- |
| データ実体 | 記録された中身そのものが取得・復元できるか |
| トランザクション | 誰が・いつ・どのような内容を記録したか |
| ブロック | その記録がチェーンのどこに含まれているか |
| ネットワーク情報 | どのチェーン・どのノードを根拠にしているか |

これらを個別に確認するだけではなく、それぞれの関係性をたどりながら検証できることが、BEYONDの中心的な機能です。

## 情報通信インフラの継続性と検証可能性

あらゆる情報システムには、設備の故障、サービスの終了、運用主体の撤退、ソフトウェアの陳腐化などのリスクがあります。ブロックチェーンも例外ではありません。

BEYONDが重視するのは、特定のサービスが停止した場合でも、必要なデータ実体とチェーン履歴を保持し、別の取得経路や検証環境を利用できる構造です。

ネットワークが現在稼働していることと、記録された情報を将来も取得・復元・検証できることは、異なる性質です。後者には、履歴に加えてデータ形式や検証手順、暗号化した場合の復号に必要な鍵などの保全も必要です。

BEYONDはこの違いを明確にし、情報の保存から将来の再検証までを一体として考えます。永久の取得を保証するのではなく、**停止後・移行後にも検証可能性を維持するための条件**を確認できるようにします。

この考え方は、[Chain Finalization](./advanced/chain-finalization.md) という終了設計や、現行機能の [BeaconとAnchor](./advanced/beacon.md) につながっています。

# BeaconとAnchor

Beaconは、ノードが自身の状態を宣言して署名したBeacon Fileを検証し、その検証対象を別のチェーンへ関連付けるための機能です。

Beaconがあるだけでノードを無条件に信頼できるわけではありません。誰が署名したか、どのネットワークとブロックを宣言しているか、現在取得できるノードの状態と一致するかを段階的に確認します。

## 検証の段階

1. **ファイルの検証**：Beacon Fileの形式、ハッシュ、署名をローカルで確認します。この段階ではノードへ接続しません。
2. **ノードとの照合**：利用者が明示的に実行したとき、ノードへ接続し、鍵、チェーン、ブロックの状態が宣言内容と一致するか確認します。
3. **Anchor**：確認したBeaconに関する記録を、別のネットワークへ書き込みます。
4. **発見**：Registryに記録された情報からBeaconやノードを探索し、ネットワーク間のAnchor関係を確認します。

## Anchorが示すこと

Anchorは、あるBeaconに関する情報が対象チェーンへ記録されたことを確認する根拠になります。元のノードが将来も応答すること、宣言内容が現実世界で真実であること、Anchor先のチェーンが永久に稼働することまでは保証しません。

再検証には、少なくとも次の情報が必要です。

- 元のBeacon File
- 署名者を確認するための鍵情報
- 宣言されたネットワークとブロックの識別情報
- Anchorを含むトランザクションと対象ネットワーク
- 検証に使用した形式と手順

## Trust Anchorとの関係

BeaconやAnchorを検証の起点として採用する場合、それはTrust Anchorの一つになります。ただし、登録されていること自体を正しさの証明とは扱いません。取得経路、署名者、確認時点、別の取得元との一致を記録し、どの前提で採用したかを明示してください。

BEYONDの信頼モデルは [BEYONDの信頼モデル](../concepts/trust-model.md)、長期的な保存の考え方は [Chain Finalization](./chain-finalization.md) を参照してください。

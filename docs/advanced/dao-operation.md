# DAOの運用

DAO（分散型自律組織）の活動を長く引き継ぐには、意思決定の仕組みと、その経緯や成果を残す仕組みが必要です。BEYONDは、議事録、提案、意思決定の結果、活動報告、制作物などをデータ実体とともにチェーンへ記録し、後から取得・復元・検証するために利用できます。

このページでは、参加者が独自チェーンの運用と履歴の保持を担い、BEYONDでDAOの歴史を蓄積する運用設計を説明します。ここで述べる組織運営や役割分担は、DAO側で定めるものです。

## 不特定多数による継続的な保存を目指す

DAOによるチェーン運用は、不特定多数の参加者がノード運用や履歴の保持を引き継ぎ、特定の運営主体が離れても保存と検証を継続できる状態を目指す試みです。

そのためには、参加を希望する人が、公開された条件と手順に従って運用に加われることが重要です。ノードの数だけでなく、誰が管理し、どこに履歴を保持し、どのように次の担い手へ引き継げるかを確認します。同じ管理者や設備に依存する複数ノードだけでは、運営主体の交代に対応できるとは限りません。

この設計が目指す永続性は、参加者の交代を通じて保存と検証を続けることです。DAOという名称やノード数だけで、ネットワークの永久稼働やデータの永久取得が保証されるわけではありません。

## 独自チェーンを選ぶ理由

DAO自身がネットワークの運用方針と履歴の継承に責任を持つなら、独自チェーンを運用基盤として検討できます。参加条件、ノードの役割、書き込み条件、費用負担、更新・移行の手順を、そのDAOの目的に合わせて設計できるためです。変更できる範囲は、採用するチェーンの仕様や実装によって異なります。

独自チェーンであることと、閉じたネットワークであることは同義ではありません。不特定多数による継続を目指す場合は、新規参加、履歴の取得、独立した検証を可能にする運用条件を用意します。

同時に、ノードの稼働、履歴の配信、ソフトウェア保守、障害対応、運用費の確保もDAO側で担います。既存ネットワークを利用する場合との違いは、これらの条件をどこまで自ら定め、継続して引き受けるかにあります。DAOの記録を保存すること自体に独自チェーンが必須という意味ではありません。

BEYONDから対象ネットワークを参照するときは、[Network Profile](../guide/network-profile.md) で識別情報と取得元を確認します。接続設定の登録だけで、ネットワークの構築やDAOの運営ルールの適用が完了するものではありません。

## BEYONDでDAOの歴史を蓄積する

記録する対象と関連付けのルールを決めると、後から参加した人も過去の活動をたどりやすくなります。

| 記録するもの | 一緒に残すと経緯をたどれる情報 |
| --- | --- |
| 規約・運営方針 | 版、適用時期、改訂理由、以前の記録への参照 |
| 提案・議事録 | 議題、検討資料、関連する提案への参照 |
| 意思決定の結果 | 対象の提案、判断に用いたルール、集計資料などの根拠 |
| 活動報告・制作物 | 関連する決定、成果物のデータ実体、改訂履歴 |
| 運用の引き継ぎ | 運用方針、公開可能な手順、対象ネットワークの識別情報 |

これらは記録内容を整理するための例であり、BEYONDの専用入力項目や自動処理を示すものではありません。秘密鍵、認証情報、公開すべきでない個人情報などを公開記録へ含めないよう、記録前に公開範囲を判断します。

訂正や改訂は、新しい記録に以前の記録への参照と変更理由を含めて残します。過去の内容とその後の判断を併せて確認できるようにすることで、参加者や運営者が交代してもDAOの歴史を継承できます。

## 保存から検証まで

1. **保存**：DAOで残すと決めた文書や成果物をBEYONDから書き込み、データ実体を含む記録として残す。
2. **取得**：対象ネットワークと記録の識別情報を共有し、別の参加者がデータ実体と必要なチェーン情報を取得する。
3. **照合**：取得したデータと記録の対応、関連記録への参照、トランザクションとブロックの関係などを比較する。
4. **検証**：照合結果と取得元などの根拠から、どの記録について何を確認できたか判断する。

書き込みと読み戻しの操作は [データを書き込む](../guide/write-data.md) と [データを検証する](../guide/verify-data.md)、保存形式は [NFTDriveの保存メカニズム](../concepts/nftdrive-storage.md) を参照してください。

BEYONDに意思決定の結果を記録することと、投票や合意形成を実施することは別です。チェーン上の記録との一致を確認できても、参加資格、投票手続き、集計方法がDAOのルールを満たしたことまでは自動的に証明されません。これらを後から確認するには、DAO側でルールと必要な根拠を残します。

## 運用を引き継げる状態を保つ

継続運用では、少なくとも次をDAO内で定め、参加者の交代に合わせて見直します。

- ノード運用、履歴保持、ソフトウェア保守を誰が担い、新たな参加者がどう加わるか。
- 保存・通信・保守の費用をどう負担し、担い手が離れたときにどう補うか。
- 必要な履歴をどこに分散して保持し、別の環境から取得・復元できることをどう確認するか。
- ネットワーク設定やクライアントの更新をどう決め、参加者へどう伝えるか。
- 障害時の復旧、運営方針が分かれた場合の扱い、移行・終了をどう判断するか。

運用手順、ネットワーク識別情報、データ形式、復元・検証に必要な仕様を引き継げる形で保全します。暗号化した記録では、復号に必要な鍵を公開履歴とは別に管理し、適切な権限を持つ人へ継承する手順も必要です。

## Chain Finalizationとの関係

DAOによる運用は、担い手の交代を通じてチェーンと履歴の保持を継続するための設計です。[Chain Finalization](./chain-finalization.md) は、停止・移行に至った場合にも記録と検証根拠を残すための終了設計です。両方を用意することで、継続中から停止・移行後までを考慮できます。

移行や終了を決めた場合は、その意思決定の根拠と対象ブロック、ネットワーク識別情報、アーカイブ、復元・検証手順を保全します。DAOによる終了の決定は、将来のブロック生成を物理的に不可能にするものではありません。どの時点の履歴を継承対象としたのかを、後から確認できるようにすることが重要です。

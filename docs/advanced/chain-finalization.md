# Chain Finalization

**Chain Finalization**は、ブロックチェーンの「終わり方」を設計するための考え方です。

多くの議論はチェーンを「どう動かし続けるか」に集中しますが、BEYONDはそれに加えて「動かなくなった後、記録をどう検証可能なまま残すか」を扱います。このページでは、その考え方を説明します。

## なぜチェーンの終了設計が必要か

ブロックチェーンは、技術的にも経済的にも、永遠の稼働を前提にできません。

- ノード運用者の減少や、経済的な持続性の限界
- 実装（クライアントソフトウェア）の保守終了
- より新しいチェーンへの移行
- 暗号方式の劣化への対応

こうした事態は「起きるかもしれない」ではなく、長い時間軸では「起こり得るものとして設計に織り込むべき」ものです。終了設計がないままチェーンが停止すると、記録は残っていても、それを検証する手段が事実上失われることがあります。

Chain Finalizationは、チェーンの停止を失敗として扱うのではなく、**検証可能性を保ったまま終了するための手続き**として定義する考え方です。

## Chain Finalizationを構成する要素

チェーンを終了する際に確定・保全すべき情報には、次のものがあります。

### 最終ブロック

チェーンの履歴の終端となるブロックです。「このチェーンの記録はこの高さ・このブロックハッシュで終わる」ことを確定します。以降のブロックが存在しないことも含めて、履歴の範囲が定まります。

### 最終ファイナリティ

最終ブロックまでの履歴が、合意形成の上で確定している（巻き戻らない）ことの確認です。ファイナリティが確認された終端であることが、アーカイブの信頼性の基盤になります。

### 最終state root

チェーンの最終状態（アカウント残高、記録された全データ等の状態）を要約するハッシュ値です。最終state rootが確定していれば、後からアーカイブされた状態データが「終了時点の正しい状態」であることを照合できます。

## 静的アーカイブへの変換

Chain Finalizationの目標は、稼働中のチェーンを**検証可能な静的アーカイブ**へ変換することです。

- 稼働中のチェーン：ノードが動き、新しいブロックが作られ、問い合わせに応答する。
- 静的アーカイブ：新しいブロックは作られないが、全履歴・最終状態・検証に必要な情報が、後から照合できる形で保存されている。

静的アーカイブに対しては、ノードの稼働がなくても、「このデータは最終state rootと整合するか」「このトランザクションは履歴に含まれるか」といった検証を行える可能性が残ります。さらに、終了時点の要約を他のチェーンへ記録しておくことで、アーカイブ自体の真正性を外部から確認する経路も作れます（[SnapshotProof](./snapshot-proof.md) を参照）。

## BEYONDでの確認方法

BEYONDでは、チェーンのファイナリゼーションに関わる情報を次の観点で確認できます。

- 対象チェーンの最終ブロック（高さ・ブロックハッシュ）
- ファイナリティの状態
- 最終state root
- 終了済みチェーンのアーカイブに対する記録の検証

これにより、稼働中のチェーンと同じ枠組みで、終了後のチェーンの記録も検証の対象として扱えます。

## 「永遠に動かす」ではなく「停止後も検証可能にする」

BEYONDの立場は明確です。

チェーンが永遠に動くことを約束するのではなく、**チェーンが止まっても記録の検証可能性が残るように設計する**。これは悲観論ではなく、長期の記録を誠実に扱うための現実的な設計姿勢です。

「ブロックチェーンに書けば安心」という言葉で終わらせず、その先の時間軸まで含めて記録を扱うこと。それがChain Finalizationの意義です。

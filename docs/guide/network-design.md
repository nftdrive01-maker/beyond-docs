# ネットワークを設計する

BEYONDのDesignerは、ブロックチェーンネットワークの計画を整理するためのツールです。BNLは独自ブロックチェーンの作成・運用を担い、BEYONDのBlockchainsは利用するネットワークへの接続を管理します。設計書を作ること、実際にノードを構築すること、接続先を登録することは別の作業です。

## Designerで計画する

左側の「Designer」を開きます。公開Web版では「ネットワーク設定」「関係者と承認」「記録データ」「データ量」「ノード」「出力」の項目が用意されています。

1. 「ネットワーク設定」で名称、説明、手数料設定、公開範囲、参加条件を整理する。
2. 「関係者と承認」で記録・運用に関わる主体と承認の方針を整理する。
3. 「記録データ」「データ量」で何をどの程度記録するかを計画する。
4. 「ノード」で保持・提供を担う構成を検討する。
5. 「出力」でプレビューを確認し、「プロジェクトを保存」で編集用の計画を保存する。「設計書を画像で保存」「設計書を印刷」で共有用の設計書を作り、構築・運用担当者と確認する。

設計値は実際のノード設定に自動的に反映されたことを意味しません。BNLでの構築時には、採用するバージョンの設定・構築手順と照合してください。

## 容量の概算を運用計画へつなげる

Designerのデータ量の見積もりを出発点に、記録件数、平均サイズ、記録頻度、運用期間を整理します。概算は実測値や容量保証ではありません。

「データ量」では冗長係数、バックアップ倍率、チャンクとインデックスのオーバーヘッドを設定し、1・3・5・10年後の容量概算を確認できます。「ノード」では総容量、月間トランザクション数、ノードあたり容量などを確認します。推奨ノード数や警告は計画の目安であり、その数を満たすだけで可用性や耐攻撃性が保証されるものではありません。

チェーン上の管理情報、ノードごとの履歴の複製、データベースの索引、ログ、一時領域、バックアップ、取得・同期の通信も必要です。個別トランザクションの上限と、期間全体で蓄積する総量を分けて評価し、試験ネットワークで実測して余裕を見込みます。

## ノード構成と運用責任

- 誰がブロック生成、履歴保持、取得APIの提供を担うか
- 災害や攻撃で同時に失われない拠点・管理権限・通信経路になっているか
- 利用者が必要な履歴をどの経路から取得できるか
- ソフトウェアの更新、監視、鍵管理、復旧訓練を誰が継続するか
- 書き込み終了後に、どの期間、どの履歴と検証根拠を残すか

参加条件を「承認制」にすることだけで、データの機密性まで確保できるわけではありません。暗号化、取得経路、参加者による複製の扱いも設計します。

構築後は [Network Profile](./network-profile.md) でネットワーク識別情報とノードを確認し、少量の記録で取得・復元・検証を試します。継続運用は [DAOの運用](../advanced/dao-operation.md)、停止・移行は [Chain Finalization](../advanced/chain-finalization.md) も参照してください。

# データを検証する

このページでは、BEYONDでデータを検証する基本的な手順を説明します。

検証とは、「データが保存されているか」ではなく、「取得したデータが、記録された時のものであると根拠をもって確認できるか」を確かめる作業です。

## 検証の全体像

BEYONDでの検証は、おおまかに次の流れで進みます。

1. 検証したい記録（Record）を指定する
2. データ実体を取得する
3. ハッシュ・メタデータを照合する
4. トランザクション情報を確認する
5. ブロック情報を確認する
6. ネットワーク情報を確認する

## Record / Asset / BlockPointer の確認

BEYONDでは、検証対象を次の単位で扱います。

- **Record**：1件の記録の全体。データ実体と検証根拠をまとめた単位です。
- **Asset**：記録されたデータ実体（ファイルやコンテンツ）を指す単位です。
- **BlockPointer**：その記録がチェーン上のどこ（どのブロック・どのトランザクション）にあるかを指し示す情報です。

検証を始めるときは、まず対象のRecordを開き、Assetの内容とBlockPointerの指す先が表示されることを確認します。

## データ実体の確認

Assetとして表示されるデータ実体が、実際に取得・復元できることを確認します。

- ファイルであれば、内容が開けるか・壊れていないか
- 分割して記録されたデータであれば、すべての断片が取得できているか

データ実体が取得できない場合、この後の照合は行えません。原因の切り分けは後述の「検証に失敗した場合」を参照してください。

## ハッシュ・メタデータの確認

取得したデータ実体から計算したハッシュ値と、記録時に残されたハッシュ値が一致するかを照合します。あわせて、メタデータ（ファイル名、サイズ、シリアル情報、署名者情報など）が記録時の内容と整合しているかを確認します。

ここが一致していれば、「取得したデータは、記録された時のデータと同一である」という根拠になります。

## トランザクション情報の確認

記録を作成したトランザクションについて、次の点を確認します。

- トランザクションがチェーン上に存在するか
- 署名者（記録を作成したアカウント）は誰か
- トランザクションの内容（記録されたデータやメタデータ）が、Recordの内容と一致するか

## ブロック情報の確認

トランザクションが含まれるブロックについて、次の点を確認します。

- BlockPointerが指すブロックが実在するか
- ブロックの高さ・ハッシュ・タイムスタンプ
- そのブロックがチェーンの確定した履歴に含まれているか（ファイナリティ）

## ネットワーク情報の確認

最後に、この検証がどのネットワークを根拠にしているかを確認します。

- 接続先のNetwork Profile（generationHash・networkType）が、意図したチェーンのものか
- 情報を取得したノードはどれか。Verified Nodeか
- ノードの健全性（Node Health）に問題はないか

ネットワークの確認は見落とされがちですが、検証の前提そのものです。詳しくは [Network Profile](./network-profile.md) を参照してください。

## 検証に成功した場合の見方

各項目の照合が一致すると、BEYONDは検証結果を根拠つきで表示します。このとき確認してほしいのは、「成功」という表示だけでなく、その内訳です。

- 何と何を照合して一致したのか
- どのノードから取得した情報に基づいているのか

BEYONDは結果だけでなく過程を表示します。過程まで確認する習慣が、検証の質を支えます。

## 検証に失敗した場合に考えられる原因

検証が失敗した場合、直ちに「データが改ざんされた」と結論づける前に、次の原因を順に確認してください。

| 症状 | 考えられる原因 |
| --- | --- |
| データ実体が取得できない | ノードが過去データを保持していない / ノードの停止 / 接続の問題 |
| ハッシュが一致しない | 取得したデータの欠損 / 参照している記録の誤り / データの不一致 |
| トランザクションが見つからない | 誤ったネットワークへの接続 / ノードの同期不足 |
| ブロック情報が確認できない | ノードが該当ブロックを保持していない / チェーンの状態の問題 |
| ネットワーク情報が一致しない | Network Profileの設定ミス / 意図と異なるチェーンへの接続 |

特に多いのは、**ネットワーク設定の誤り**です。別のネットワークに接続した状態では、正しい記録も「存在しない」ように見えます。検証に失敗したら、まずNetwork Profileを確認することをおすすめします。

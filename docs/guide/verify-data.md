# データを検証する

Verified Browserは、ブロックチェーン上の記録を検索し、データ実体、トランザクション、ブロック、ネットワーク、取得元の関係を確認するための画面です。

プレビューが表示されたことだけを、検証完了とは扱いません。どの情報を取得し、何と照合できたかを確認してください。

初めて開く方は、[5分で体験するBEYOND](./quickstart.md) の実例から始められます。記録を開いた後は、プレビュー上部の「詳細情報」で、記録者、データアドレス、ネットワーク、ブロック高、完全性などを確認します。

## 検証の流れ

1. 記録アドレス、ネームスペース、共有URLなどから対象を開く。
2. データ実体を取得し、復元状態を確認する。
3. 記録されたメタデータと、復元した内容の関係を確認する。
4. トランザクションと対象ブロックを確認する。
5. 対象ネットワークと取得元ノードを確認する。
6. 警告、未確認項目、暗号化状態を含めて結果を判断する。

## データ実体と完全性

一覧から対象ファイルを開き、内容が取得・復元できることを確認します。分割された記録では、必要なチャンクがそろっている必要があります。

記録の途中で書き込みが止まり、必要な部分がチェーン上に存在しない場合、BEYONDは不完全な記録として表示します。取得元を変えても欠けたトランザクション自体が存在しなければ、後から完全なデータへ復元することはできません。

記録形式によっては、独立したオンチェーンのコンテンツハッシュが存在しない場合があります。その場合、復元成功やローカルで計算したハッシュだけを、初回取得内容の独立証明とは扱えません。

## トランザクションとブロック

詳細情報から、少なくとも次を確認します。

- 記録に対応するトランザクション識別子
- 記録アドレスとデータアドレス
- ブロック高、ブロックハッシュ、記録時刻
- 対象トランザクションがブロックに含まれていること
- 必要な場合は、対象ネットワークで観測できる確定状態

署名者情報は、対応する鍵でトランザクションが作成されたことを示します。表示名、メタデータ上の作成者、現実世界の人物が同一であることは別に確認します。

## ネットワークと取得元

同じアドレスやネームスペースが複数ネットワークに存在する場合があります。次を確認してください。

- 表示中のネットワーク名とgenerationHash
- 情報を返したノード
- ノードの応答状態とブロック高
- 別の取得元でも同じトランザクションやブロック情報を得られるか

単一ノードの応答や「SYNCED」という表示だけで、ネットワーク全体や記録内容の真実性が保証されるわけではありません。

## ネームスペースから開いた場合

ネームスペースは、所有者が参照先を変更できます。ネームスペースの所有者と記録者が異なる場合、BEYONDは警告します。

これは直ちに不正を意味するものではありませんが、第三者が別の記録へ名前を付けている可能性があります。ネームスペースだけでなく、記録アドレスとトランザクションも確認してください。

## 暗号化された記録

暗号化された記録には鍵アイコンと暗号化状態が表示されます。

- 対応する暗号化キーがアンロックされていれば、デスクトップ版で自動復号できます。
- 共有パスワード付きなら、対応するWeb版や単体ビューアでも復号できます。
- 復号できたことは、記録内容が真実であることや共有パスワードが十分強いことを意味しません。

復号方法と鍵の管理は [ファイルを暗号化する](./file-encryption.md) を参照してください。

## プレビュー内のスクリプト

HTMLなどの記録にはスクリプトが含まれる場合があります。既定では、記録由来のスクリプトを停止した状態で表示し、利用者が明示的に許可した場合だけ実行します。

出所や内容を確認できない記録では実行しないでください。「常に実行する」設定は、信頼できない記録を開く用途には適しません。プレビューの隔離はリスクを減らしますが、未知の脆弱性まで保証するものではありません。

## 失敗や警告の読み方

| 状態 | 主な確認先 |
| --- | --- |
| データを取得できない | ノードの停止、履歴保持範囲、ネットワーク設定、接続方式 |
| 記録が不完全 | 必要なトランザクションやチャンクがチェーン上に存在するか |
| トランザクションが見つからない | 対象ネットワーク、ノードの同期、識別子 |
| 複数ノードで応答が異なる | ブロック高、同期状態、取得時点、ネットワーク識別情報 |
| 暗号化ファイルを開けない | 対応する暗号化キー、ロック状態、共有パスワード、対応形式 |
| ネームスペースの警告 | 所有者、記録者、現在の参照先 |

取得不能や不一致は重要な結果ですが、それだけで改ざんと断定しないでください。確認できた範囲と、確認できなかった理由を分けて記録します。

# Network Profile

Network Profileは、BEYONDがどのネットワークを、どのノード経由で参照するかを定義する設定です。現在の画面では、パブリックチェーンと組織内・ローカルのプライベートチェーンをBlockchainsで管理します。

## ネットワークを識別する情報

代表的な項目は次のとおりです。

| 項目 | 役割 |
| --- | --- |
| generationHash | チェーンの起点に関係する識別情報。意図したチェーンかを照合する中心的な値 |
| networkType | アドレス形式などの解釈に使うネットワーク種別 |
| epochAdjustment | チェーン内部時刻を日時へ変換する基準 |
| REST Node | ブロック、トランザクション、アカウントなどを取得するAPI |
| Peer Node | ブロックの生成・伝播に参加するネットワーク上のノード |

Network Profileが登録されていること自体は、設定内容が正しいことの証明ではありません。generationHashなどの期待値を、信頼できる配布元や独立して保管した情報と照合してください。

## パブリックとプライベート

BEYONDでは、ネットワークをパブリックまたはプライベートとして管理できます。この区分は接続範囲と運用意図を表す設定であり、generationHashから自動的に証明される性質ではありません。

プライベートとして設定したネットワークに、外部から到達できるノードが含まれる場合は、閉域という運用意図と実際の到達性が一致しているか確認してください。

## ノードの状態

ノードごとに応答可否、観測したブロック高、同期状態などを確認できます。「SYNCED」は観測時点で比較対象へ追い付いていることを示す状態であり、ノードの応答が常に完全・正確であることを保証しません。

Verified Nodeという区分が表示される場合も、絶対に正しいノードを意味しません。どの条件を確認した区分なのかを、表示内容と利用中のバージョンに基づいて判断してください。

## デスクトップ版とWeb版の違い

- デスクトップ版は、利用者が明示的に実行したときにLAN内のノードを検出し、プライベートチェーンへ接続できます。
- Web版はブラウザの制約により、LAN内のHTTPノードを検出・直接接続できません。
- HTTPSノードへWeb版から接続するには、ノード側のCORS設定が必要です。
- Web版のHTTP中継は、配信環境で機能が有効化され、対象ノードが許可されている場合に限られます。

詳しくは [デスクトップ版とWeb版](./editions.md) を参照してください。

## ノードの自動修正

BEYONDは、応答しないノードを外し、同じネットワークで応答するノードを候補として追加する機能を持ちます。ただし、候補が同じチェーンに属するか、運用上利用してよいかは、generationHashや接続方針を含めて確認してください。

## 接続できない場合

1. ノードURLと到達性を確認する。
2. generationHashが意図したネットワークと一致するか確認する。
3. networkTypeとepochAdjustmentを確認する。
4. ノードのブロック高と同期状態を確認する。
5. デスクトップ版とWeb版の接続制約に該当しないか確認する。
6. 別の取得元でも同じ結果になるか確認する。

データが見つからない場合は、記録が存在しないと判断する前に、対象ネットワークと取得元を確認してください。信頼モデルの背景は [BEYONDの信頼モデル](../concepts/trust-model.md) を参照してください。

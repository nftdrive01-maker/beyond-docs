# Network Profile

Network Profileは、BEYONDが「どのネットワークを、どのノード経由で見ているか」を定義する設定のまとまりです。

検証の結果は、意図したネットワークを参照していることを前提とします。Network Profileは、その前提を人間が確認できる形にしたものです。

## Network Profileとは

1つのNetwork Profileには、ネットワークを特定し、接続するために必要な情報が含まれます。

- generationHash
- networkType
- epochAdjustment
- REST Node の一覧
- Peer Node の情報
- Verified Node の状態
- Node Health の情報

## generationHash

**generationHash**は、チェーンの起点（ジェネシス）から導出される、そのチェーン固有の識別子です。

同じ系統のチェーンでも、メインネットとテストネットではgenerationHashが異なります。検証や書き込みの前にgenerationHashを確認することで、「意図したチェーンに接続しているか」を判定できます。BEYONDにおける最も基本的なネットワーク確認手段です。

## networkType

**networkType**は、ネットワークの種別（メインネット / テストネットなど）を示す値です。アドレスの形式にも影響するため、networkTypeが誤っていると、アカウントやトランザクションの解釈も誤ります。

## epochAdjustment

**epochAdjustment**は、チェーン内部の時刻表現を実際の日時に変換するための基準値です。ブロックやトランザクションのタイムスタンプを人間が読める日時として表示するために使われます。この値が誤っていると、表示される日時がずれます。

## REST Node

**REST Node**は、BEYONDがチェーンのデータを取得するために接続するAPIサーバーです。ブロック、トランザクション、アカウント情報などは、REST Node経由で取得します。

REST Nodeは誰でも運用できるため、ノードごとに保持しているデータの範囲や健全性は異なります。

## Peer Node

**Peer Node**は、チェーンのネットワークを構成するノードです。ブロックの生成や伝播を担います。BEYONDの利用では主にREST Nodeと通信しますが、ネットワーク全体の健全性はPeer Nodeの状態に支えられています。

## Verified Node

**Verified Node**は、BEYONDが定めた確認条件を満たした取得元、または検証対象として登録されたノードを区別するための状態です。絶対に正しいノードを意味しません。

確認条件には、generationHashなどのネットワーク識別情報、応答可否、同期状態、他の取得元との一致などが含まれ得ます。実際に確認した条件は、利用中の実装と表示内容に従って判断してください。Verified Nodeの仕組みは、「どの情報源に、どの条件で依存しているか」を利用者が把握するためのものです。詳しい背景は [BEYONDの信頼モデル](../concepts/trust-model.md) を参照してください。

## Node Health

**Node Health**は、ノードの健全性（応答するか、同期しているか、どの高さまでデータを持っているか）を示す情報です。検証に失敗した場合の原因切り分けにも役立ちます。

## テストネット / メインネット / 独自チェーン

Network Profileは複数登録でき、切り替えて使用します。

- **テストネット**：試験用のネットワーク。動作確認や練習に適しています。記録の永続性は期待できません。
- **メインネット**：本番のネットワーク。実際の記録にはこちらを使います。
- **独自チェーン**：組織やプロジェクトが独自に運用するチェーン。generationHash等の情報を登録することで、BEYONDから接続できます。

## BNLチェーンの登録

BNL（独自チェーン）を利用する場合は、そのチェーンのNetwork Profile（generationHash・networkType・epochAdjustment・ノードURL）を登録します。登録後、generationHashが期待値と一致することを確認してから利用を開始してください。

## 接続できない場合の確認点

接続や検証がうまくいかない場合、次の順で確認してください。

1. **ノードのURL**は正しいか。到達できるか（メンテナンスや停止の可能性）。
2. **generationHash**は意図したチェーンのものか。
3. **networkType**は一致しているか。
4. **Node Health**に問題はないか。同期が遅れていないか。
5. 別のノードに切り替えた場合、同じ結果になるか。

データが見つからない場合は、データ自体の状態を判断する前に、ネットワーク設定と取得元を確認してください。

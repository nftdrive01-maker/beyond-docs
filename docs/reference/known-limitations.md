# 既知の制限

このページでは、BEYONDおよびブロックチェーン上の記録に関わる、既知の制限とリスクをまとめます。

これらを明示するのは、不安を与えるためではありません。限界を知った上で使うことが、記録を長期にわたって扱うための前提だと考えているためです。あわせて [BEYONDが保証すること / 保証しないこと](../concepts/guarantees.md) もご覧ください。

## チェーン自体の停止リスク

ブロックチェーンは、経済的な持続性の限界、参加者の減少、移行などにより、停止する可能性があります。ただし、停止には異なる状態があります。

| 状態 | 取得・検証への影響 |
| --- | --- |
| 新しいブロックの生成が停止 | 履歴を提供するノードが稼働していれば、記録済みデータを取得できる場合がある |
| 接続先ノードが停止 | 同じ履歴を保持・提供する別のノードやアーカイブが必要 |
| 必要な履歴や復号鍵が失われた | ブロック識別情報やハッシュだけではデータ実体を復元できない |

ネットワークの稼働、データの可用性、保全された履歴の検証可能性を分けて判断します。

BEYONDはこのリスクを設計で直視し、[Chain Finalization](../advanced/chain-finalization.md) という終了設計と、現行機能の [BeaconとAnchor](../advanced/beacon.md) によって検証根拠を残す考え方を採用しています。ただし、履歴やアーカイブ本体が保全されなければ、外部の証明情報だけからデータ実体を復元することはできません。

## ノード停止リスク

個々のノードは、運用者の判断でいつでも停止し得ます。特定のノードだけに依存していると、そのノードの停止が取得・検証の障害になります。複数ノードの登録と、Verified Node・Node Healthによる状態確認を活用してください。

## 過去データ取得不能リスク

必要な履歴を保持しているか、外部から取得できるAPIを提供しているかは、ネットワークとノードの構成によります。全履歴を保持するノードやアーカイブでも、取得経路や復元仕様が利用できることを確認してください。「チェーンに記録されていること」と「今接続しているノードから取得できること」は別です。

## 災害・攻撃からの復旧

ノード数を増やすだけでは、災害やランサムウェアへの耐性は保証されません。同じ拠点、管理アカウント、クラウド、電源などを共有すると、複数のコピーが同時に失われる可能性があります。

独立した拠点・管理主体への履歴の複製、別系統のアーカイブ、鍵と復元仕様の保全、復旧訓練を組み合わせます。残存する履歴から復元できることと、取得内容が記録と対応していることを、それぞれ確認してください。

## ネットワーク設定ミス

誤ったNetwork Profile（別チェーン・別ネットワーク）に接続した状態では、対象ネットワークに存在する記録も「存在しない」ように見え、検証結果も意図した対象を示しません。generationHashを確認してください（[Network Profile](../guide/network-profile.md) を参照）。

## 秘密鍵紛失

署名用の秘密鍵とそのバックアップを失うと、その鍵を必要とする新たな書き込みや操作はできなくなります。BEYONDが鍵を再発行することはできません。公開済みの平文データの取得に、署名用の秘密鍵が必要になるわけではありません。

ファイル暗号化の復旧フレーズは、送金用の秘密鍵とは別の情報です。通常の設定エクスポートにも含まれません。復旧フレーズと暗号化キーを保存した端末の両方を失うと、暗号化したファイルを復号できない可能性があります。

## 個人情報保存の注意

パブリックネットワークの平文データは、第三者が取得・閲覧できる前提で扱います。暗号化した場合も暗号文や履歴は取得・複製され得ます。プライベートネットワークの参加制御は取得経路を制限しますが、参加者による複製や持ち出しまで防ぐものではなく、データの機密性と同一ではありません。

誤記は訂正・改訂を新しい記録として追加し、元の記録との関係を示すことで扱えます。ただし、訂正は過去の履歴や第三者のコピーを物理的に消去することではありません。保存前に情報を分類し、公開範囲、暗号化、保管期間、削除要件に適した保存方式を選んでください。

## 暗号化データの長期リスク

公開ネットワークに記録した暗号文は、第三者に長期間保管される可能性があります。暗号方式は、計算能力の向上や新しい攻撃手法により、時間とともに弱くなる可能性があります。鍵の漏えいで内容が読まれる場合もあり、「現在安全な暗号化」が将来も安全である保証はありません。将来の公開も許容できない情報は、暗号化だけを根拠に記録しないでください。

暗号化されるのはファイル本体であり、ファイル名、説明、シリアル情報などのメタデータは平文で記録される場合があります。また、共有パスワードを設定したファイルは、そのパスワードを知る人が復号できます。一度記録した共有パスワードの効力を、過去の記録から取り消すことはできません。

## ファイルサイズと実行環境

Base64保存モードには、全体をJavaScript文字列として扱うことに由来する既知の上限があります。バイナリ保存モードはこの固定上限を回避しますが、任意サイズを保証するものではありません。

暗号化・復号はファイル全体をメモリで扱うため、端末のメモリ、アプリ内部のデータ受け渡し、ブラウザ、ノード、ネットワーク、手数料などの制約を受けます。書き込めたファイルが、別の端末で必ず復元できるとは限りません。詳細は [記録サイズの制約](./record-size-limits.md) を参照してください。

## デスクトップ版とWeb版の差

Web版では、新しいファイルを暗号化して記録すること、Verified Driveを使うこと、LAN内ノードを検出・直接接続することはできません。ブラウザのサイトデータを削除すると、Web版に保存された設定や状態も失われます。

デスクトップ版でも、OSのスリープ・終了中に処理を続けることはできません。対応範囲は [デスクトップ版とWeb版](../guide/editions.md) を参照してください。

## Verified Driveの信頼境界

Verified Driveのローカルハッシュは、初回取得した内容から計算するTOFUの基準です。独立したオンチェーンのコンテンツハッシュと照合する場合とは異なり、初回取得内容が正しかったことをハッシュ単独では保証しません。

また、BEYONDを終了している間はリアルタイム監視できず、ローカルの状態ファイル自体が改変された場合は検知を回避される可能性があります。詳しくは [Verified Drive](../guide/verified-drive.md) を参照してください。

## 記録由来のコンテンツ

HTMLなどの記録にはスクリプトが含まれる場合があります。BEYONDは既定でスクリプトを停止し、表示を隔離しますが、未知の脆弱性まで排除するものではありません。出所や内容を確認できない記録では、スクリプトを実行しないでください。

## 外部システム依存

記録や検証のフローに外部システム（外部ストレージ、外部API、DNS等）が関与する場合、その部分の可用性・永続性は外部システムに依存します。BEYONDの検証対象の外側にある依存は、BEYONDでは保証できません。

## 将来的な暗号方式の変化

チェーンの署名やハッシュに使われている暗号方式自体も、長期的には世代交代が必要になる可能性があります（量子計算機への耐性など）。これはブロックチェーン全般の課題であり、再証明・再アンカーといった対応の検討領域です。BEYONDはこの変化を「起こり得るもの」として扱います。

## BEYONDのバージョン差異

BEYOND自体もソフトウェアであり、バージョンによって対応機能・表示・検証手順の詳細が異なる場合があります。検証結果を記録として残す場合は、使用したBEYONDのバージョンもあわせて記録しておくことをおすすめします。また、BEYONDという実装自体に依存しすぎないよう、検証手順の根拠を公開する方針を取っています（[BEYONDの信頼モデル](../concepts/trust-model.md) を参照）。

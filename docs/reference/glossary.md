# 用語集

BEYOND Docsで使用する用語を定義します。

## 保存

データまたは記録を永続的な媒体へ配置する行為。ブロックチェーンへのトランザクション送信を指す「書き込み」とは区別する。

## 書き込み

トランザクションとしてブロックチェーンへ送信する行為。送信した時点ではチェーン上の記録になったとは限らず、対象ブロックへの包含などを別に確認する必要がある。

## 取得

保存されたデータやチェーン情報を、ノード、アーカイブ、外部ストレージなどの取得元から読み出す行為。

## 照合

取得した情報同士のハッシュ、識別子、参照関係などを比較する行為。

## 検証

照合結果と検証根拠をもとに、記録の状態が定めた検証条件を満たすか判断する行為。

## 記録

ブロックチェーン上に確定したトランザクションまたはデータ。送信中のトランザクションとは区別する。

## データ実体

復元・表示・利用の対象となる元データ。ハッシュ、識別子、参照情報だけを指すものではない。

## チェーン

ブロックが連なって形成された履歴。チェーンを共有・維持するノード群と設定を指す「ネットワーク」とは区別する。

## ネットワーク

チェーンを共有・維持するノード群と、その識別・運用に必要な設定。

## BEYOND

ブロックチェーンに記録されたデータを、後から人間が検証できる形で扱うための検証ブラウザ。データ実体・ブロック・トランザクション・ネットワーク情報・検証根拠の確認を支援する。保存ツールではなく、検証可能性を人間が扱える形にするためのプロダクト。

## NFTDrive

フルオンチェーンでのデータ記録を扱うプロジェクト・エコシステム。BEYONDはこのエコシステムにおける検証ブラウザとして位置づけられる。

## BNL

NFTDriveのエコシステムにおける独自ブロックチェーン。BEYONDからはNetwork Profileを登録することで接続・検証できる。

## Record

BEYONDにおける1件の記録の単位。データ実体（Asset）と、その検証根拠（トランザクション・ブロック・ネットワーク情報への参照）をまとめて扱う。

## Asset

Recordに含まれるデータ実体。記録されたファイルやコンテンツそのものを指す。

## BlockPointer

記録がチェーン上のどこにあるか（どのブロック・どのトランザクションか）を指し示す参照情報。Recordとチェーン上の根拠を結びつける。

## Network Profile

接続先ネットワークを特定・設定するための情報のまとまり。generationHash、networkType、epochAdjustment、ノード一覧などを含む。検証の前提となる「どのチェーンを見ているか」を明示する。

## Verified Node

BEYONDが定めた確認条件を満たした取得元、または検証対象として登録されたノードを区別するための状態。絶対に正しいノードを意味せず、実際に確認した条件は実装と表示内容に依存する。

## Trust Anchor

検証を始めるために基準として採用する、外部から確認・保持された根拠。期待するgenerationHash、既知のブロックハッシュ、独立した媒体に保存した外部証明などが候補になる。採用した理由、取得元、取得時点を明示する必要がある。

## generationHash

チェーンの起点（ジェネシス）から導出される、チェーン固有の識別子。接続先が意図したチェーンであるかの確認に使う。

## networkType

ネットワークの種別（メインネット / テストネット等）を示す値。アドレス形式の解釈にも関わる。

## epochAdjustment

チェーン内部の時刻表現を実際の日時へ変換するための基準値。ブロックやトランザクションのタイムスタンプ表示に使われる。

## REST Node

チェーンのデータをAPIとして提供するノード。BEYONDはブロック・トランザクション・アカウント情報等をREST Node経由で取得する。

## Peer Node

チェーンのネットワークを構成し、ブロックの生成・伝播を担うノード。

## Full On-chain（フルオンチェーン）

データ実体そのものをチェーン上のトランザクションに含めて記録し、データ実体をチェーンの検証対象に含める方式。すべてのデータを無制限に保存する思想ではなく、検証に必要な実体をチェーンに置く設計判断を指す。

## Hash Reference（ハッシュ参照）

データのハッシュ値のみをチェーンに記録し、データ実体はチェーン外で保管する方式。軽量で改ざん検知に有効だが、実体が失われると中身の確認はできなくなる。

## External Storage（外部ストレージ）

IPFS・Arweave・クラウドストレージ等、チェーン外でデータ実体を保持するシステム。大容量データの保持に強みがあり、フルオンチェーンとは目的が異なる設計。

## Chain Finalization

チェーンの終了を、検証可能性を保ったまま行うための設計・手続き。最終ブロック、最終ファイナリティ、最終state rootを確定し、チェーンを検証可能な静的アーカイブへ変換する考え方。

## SnapshotProof

チェーンの特定時点の状態の要約（ブロック高・ブロックハッシュ・state root・proofJson）を、後から照合可能な証拠として構成したもの。複数チェーンへのアンカーにより、チェーン終了後の検証の根拠にもなる。

## Re-verifiability（再検証性）

一度検証された記録を、後の時点（チェーンの停止後や環境の変化後を含む）でも再び検証できる性質。BEYONDが長期の記録に対して重視する設計目標。

## Archive Node

チェーンの全履歴（過去のすべてのブロック・状態）を保持するノード。過去データの取得・再検証に必要となる。すべてのノードが全履歴を保持するわけではない。

## State

チェーンのある時点における全体の状態。アカウントの残高、記録されたデータ、設定などの総体。state rootによって要約される。

## Finality（ファイナリティ）

ブロックがチェーンの履歴として確定し、巻き戻らないことが保証された状態。ファイナリティが確認されたブロックに含まれる記録は、履歴として確定したものとして扱える。

## Transaction（トランザクション）

チェーンに対する操作の単位。データの記録も、署名されたトランザクションとしてチェーンに送信される。誰が・いつ・何を記録したかの根拠となる。

## Block（ブロック）

複数のトランザクションをまとめ、チェーンの履歴に追加する単位。高さ（block height）とブロックハッシュで特定される。

## Metadata（メタデータ）

データ実体に付随する情報。ファイル名、説明、シリアル情報、署名者情報など。記録の検索・文脈理解・照合の手がかりとなり、記録の一部としてチェーンに残る。

# 記録サイズの制約

記録できるファイルサイズは、保存モードと暗号化の組み合わせで異なります。

| 保存モード | 暗号化 | 既知の固定上限 |
| --- | --- | --- |
| バイナリ | なし | Base64全体文字列に由来する固定上限なし |
| バイナリ | あり | Base64全体文字列に由来する固定上限なし |
| Base64 | なし | 383MB |
| Base64 | あり | 287MB |

ここでいう「固定上限なし」は、任意のサイズを記録できるという意味ではありません。メモリ、アプリ内部のデータ受け渡し、暗号化・復号処理、ネットワーク設定、ノードの制約、手数料、空き容量などによる上限は残ります。

## バイナリ保存モード

バイナリ保存モードは、ファイル全体をBase64文字列へ変換せずに分割するため、JavaScriptの文字列長に由来する固定上限を回避します。Base64化による膨張も避けられるため、同じファイルなら記録量をおおむね25%削減できます。

対応していない古いビューアでは、バイナリ保存モードの記録を開けない場合があります。長期利用では、記録形式と対応する読み取り手段も一緒に保全してください。

## Base64保存モード

Base64保存モードでは、ファイルを1本の文字列として扱う工程があります。暗号化すると、さらに暗号化形式の文字列表現が加わるため、平文より小さい上限になります。

既知の上限を超えるファイルは、記録開始前に画面で止めます。ただし、上限内であることは送信成功を保証しません。送信開始後の通信障害や残高不足などにより、途中までのトランザクションが残る場合があります。

## 読み戻しにも制約がある

暗号化していない大きな記録は、対応する経路では分割して取得できます。暗号化された記録は復号時に全体を必要とするため、利用可能なメモリなど実行環境の影響を強く受けます。

ある環境で書き込めたファイルを、別の端末やブラウザで必ず復元できるとは限りません。大きなファイルは、記録後に実際の利用環境で読み戻せることを確認してください。

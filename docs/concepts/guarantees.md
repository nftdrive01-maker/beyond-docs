# BEYONDが保証すること / 保証しないこと

BEYONDの検証結果は、取得できた情報、実行した照合、対象ネットワーク、取得元、検証条件によって範囲が決まります。このページでは、BEYONDが根拠を提示できる範囲と、そこからは判断できない範囲を分けます。

## BEYONDが保証すること

BEYONDが保証するのは、すべての検証が成功することではありません。利用中の機能と取得できた情報の範囲で、何を取得・照合し、どの条件に基づいて判断したかを、確認できる根拠とともに示すことです。確認できない項目は、成功として扱わず、取得不能、根拠不足、未確認などの状態として区別します。

確認の対象になり得る項目は次のとおりです。

| 確認対象 | 確認できる内容 | 主な前提 |
| --- | --- | --- |
| データの取得 | データ実体または記録が、示された取得元から読み出せたこと | 取得元が応答し、必要な履歴や実体を保持していること |
| ハッシュ・識別情報 | 取得したデータから計算したハッシュや識別情報 | 計算方法、データ形式、暗号方式が特定されていること |
| トランザクションとの対応 | データ実体のハッシュ、識別情報、参照関係などがトランザクションの記録内容と一致すること | 対応規則と対象トランザクションを特定できること |
| ブロックへの包含 | 対象トランザクションが取得したブロック情報に含まれていること | ブロックとトランザクションを取得・解釈できること |
| 対象ネットワーク | generationHashなどが、Network Profileの期待値と一致すること | Profileの期待値自体を別の根拠から確認していること |
| 取得元ノード | どのノードから情報を取得したか、その応答や状態 | 取得元情報と確認時点を記録できること |
| 複数取得元間の一致 | 複数の取得元から得た対象情報が一致すること | 比較対象、ブロック高、取得時点などの条件がそろっていること |
| 外部証明との一致 | SnapshotProofなど、利用可能な外部証明に含まれる値と一致すること | 証明形式、Trust Anchor、照合手順を確認できること |

これらは一律に常時保証されるのではなく、対象ネットワーク、ノード、BEYONDのバージョン、利用可能な機能とデータによって確認可能な項目が異なります。結果には、成功・不一致だけでなく、取得不能、根拠不足、未確認も含まれます。

一致が確認できた場合でも、表現は確認できた範囲に限定します。たとえば「取得したデータのハッシュが記録内容と一致している」「トランザクションが対象ブロックに含まれている」「指定されたネットワークの複数取得元で応答が一致している」と示します。

## BEYONDが保証しないこと

### 記録内容の真実性

チェーン上の記録とデータ実体の一致を確認できても、その内容が社会的・法的・事実的に真実であるとは限りません。入力者の説明が真実であること、記録前のデータに誤りがないことも保証しません。

### 鍵と現実世界の人物の同一性

署名は、対応する秘密鍵によってトランザクションが作成されたことを確認する根拠になります。しかし、秘密鍵の所有者と、表示名や現実世界の人物・組織が同一であることは、別の本人確認や運用上の根拠がなければ保証できません。

### ネットワークとデータの永続性

ネットワークが永久に稼働すること、ノードが永久に応答すること、チェーン履歴やデータ実体が永久に取得できることは保証しません。停止・移行後の再検証には、履歴、アーカイブ、外部証明、検証手順などを別途保全する必要があります。

### 暗号方式の永続的な安全性

現在使用されるハッシュ、署名、暗号化方式が将来も同じ安全性を保つことは保証しません。長期保存では、方式の識別、再評価、必要に応じた再証明を検討します。

### 単一ノードの応答

単一ノードの応答が常に最新、完全、または記録内容と一致していることは保証しません。Verified Nodeも絶対に正しいノードを意味しません。複数取得元との照合は依存を減らしますが、共通の障害や同じ運用主体への依存までは排除できない場合があります。

### BEYONDの画面とローカル環境

BEYONDの画面自体が改変されていないこと、ローカルソフトウェアや依存ライブラリが常に意図したとおり動作することは、画面表示だけでは保証できません。重要な検証では、バージョンと設定を記録し、取得元や計算結果を独立した手段でも確認します。

### 外部システムと設定

外部ストレージ、外部API、名前解決、配布元などの可用性・永続性は、それぞれの運用に依存します。また、誤ったNetwork ProfileやTrust Anchorを使えば、手順どおりに照合しても意図したネットワークの検証にはなりません。

## 長期の検証に向けて

保証できない範囲があることは、検証を諦める理由ではありません。取得元、検証時点、ネットワーク識別情報、照合した値、ソフトウェアのバージョンを残し、可能なら複数の独立した根拠を用意することで、停止後・移行後の再検証可能性を高められます。

[Chain Finalization](../advanced/chain-finalization.md) と [SnapshotProof](../advanced/snapshot-proof.md) は、そのための考え方と検証材料を扱います。ただし、それらが存在するだけで停止後の取得や検証が自動的に保証されるわけではありません。必要なアーカイブと手順が利用でき、外部証明との照合条件を満たすことが前提です。

> BEYONDは、すべてを保証するプロダクトではありません。保証できる範囲を明確にし、保証できない部分についても、利用者が根拠を確認できる環境を提供します。

# BEYONDの信頼モデル

> BEYONDは、BEYOND自身を無条件に信頼することを要求しません。表示された情報の取得元と検証根拠を、利用者自身が確認できる状態を目指します。

検証結果には必ず前提があります。BEYONDの役割は前提を隠して一つの判定を示すことではなく、データ実体、トランザクション、ブロック、ネットワーク、取得元の関係と、そこで行った照合を確認できるようにすることです。

## 何を信頼し、何をそのまま信頼しないか

| 対象 | BEYONDでの扱い |
| --- | --- |
| 暗号学的ハッシュや署名 | 使用した方式が前提とする性質に依存し、計算結果や署名情報を検証根拠として扱う |
| チェーンの合意とファイナリティ | 対象ネットワークの方式と観測できた状態に依存し、ブロックの包含・確定状態を確認する |
| ノードの応答 | 単一の応答を絶対視せず、ネットワーク識別情報、応答内容、同期状態、別の取得元との一致を確認する |
| Network Profile | 接続先と期待値を明示する設定として使うが、登録内容が正しいこと自体は別の根拠で確認する |
| BEYONDの画面 | 取得・照合した内容を理解する入口として使うが、画面表示だけをチェーン上の事実とはみなさない |
| 記録の説明や意味 | チェーン上に記録された内容として確認するが、現実世界での真実性までは推定しない |

## アプリケーション表示とチェーン上の記録

BEYONDの画面は、ノードなどから取得した情報をソフトウェアが解釈して表示したものです。チェーン上の記録そのものと、アプリケーションによる表示・説明は区別する必要があります。

たとえば「検証済み」という表示だけでは、何が確認されたかは分かりません。取得したデータ実体、計算したハッシュ、トランザクション識別子、対象ブロック、ネットワーク識別情報、取得元、適用した検証条件を合わせて確認することで、表示の根拠を追跡できます。

## Network Profileの役割

**Network Profile**は、対象ネットワークを識別し、取得元へ接続するための期待値と設定をまとめたものです。generationHash、networkType、epochAdjustment、ノード一覧などによって、「どのネットワークを、どの取得元から確認しているか」を明示します。

Network Profileは検証の前提を可視化しますが、設定ファイルであること自体が正しさの証明になるわけではありません。generationHashなどの期待値を、公式に配布された設定、既知のブロック情報、独立して保管した資料などのTrust Anchorと照合する必要があります。項目の詳細は [Network Profile](../guide/network-profile.md) を参照してください。

## Verified Nodeの役割

**Verified Node**は、絶対に正しいノードを意味しません。BEYONDが定めた確認条件を満たした取得元、または検証対象として登録されたノードを区別するための状態です。

確認条件には、想定するネットワーク識別情報との一致、応答可否や同期状態、他の取得元との応答の一致などが含まれ得ます。実際にどの条件を確認したかは、表示される状態や利用中の実装・バージョンに依存します。Verified Nodeというラベルだけで、将来の応答、全履歴の保持、運用者の信頼性、単独応答の完全性が保証されるわけではありません。

## 複数ノード照合の意味

複数のノードから取得した情報が一致すれば、単一ノード固有の障害、同期遅延、不正確な応答に依存している可能性を下げられます。また、どのノードからいつ取得したかを残せば、後の再検証にも役立ちます。

ただし、複数ノードの一致は、その時点で観測した応答が一致したことを示すものです。ノードが同じ運用者や同じ上流データに依存している場合もあり、ネットワーク全体の健全性や記録内容の真実性を単独で保証するものではありません。取得元の独立性、同期状態、対象ブロック高も合わせて評価します。

## ローカルソフトウェアの改変リスク

BEYOND自体も改変され得るソフトウェアです。ローカルの実行ファイル、依存ライブラリ、設定、ブラウザ上のコードが変更されれば、取得・計算・表示のいずれかが意図と異なる可能性があります。

重要な検証では、利用したBEYONDのバージョンと設定を記録し、可能なら別の実装や独立した計算手段でもハッシュやチェーン情報を照合します。配布物の真正性を確認できる情報が提供されている場合は、それも検証根拠に含めます。

## Trust Anchor

**Trust Anchor**は、検証を始めるために基準として採用する、外部から確認・保持された根拠です。たとえば、期待するgenerationHash、既知のブロックハッシュ、信頼する配布経路から得たNetwork Profile、独立した媒体に保存したSnapshotProofなどが候補になります。

Trust Anchorは「無条件に正しい情報」という名称ではありません。誰が、どの時点で、どの経路から取得し、なぜ基準として採用するかを明示する必要があります。異なる主体や媒体に由来する複数の根拠を使えば、単一の配布元への依存を減らせます。

BEYONDは、Trust Anchorを利用者に代わって絶対化するのではなく、どの根拠からどの照合結果へ到達したかを追える状態を目指します。保証の境界は [BEYONDが保証すること / 保証しないこと](./guarantees.md) を参照してください。

# BEYONDの信頼モデル

どんな検証ツールにも、「何を検証し、何に依存しているか」という前提があります。このページでは、BEYONDの信頼モデル、つまりBEYONDが検証するものと、BEYONDが依存するものを明示します。

BEYOND自体を盲信するのではなく、検証の手順と前提を理解した上で使っていただくことが、このプロダクトの思想です。

## BEYONDが検証するもの

BEYONDは、次の項目を検証・確認の対象とします。

- **データ実体とハッシュの照合** — 取得したデータが、記録されたハッシュと一致するか。
- **トランザクションの存在と内容** — 記録を作成したトランザクションがチェーン上に存在し、署名者・内容が確認できるか。
- **ブロックへの包含** — トランザクションがどのブロックに含まれ、そのブロックがチェーンの履歴に確定しているか。
- **ネットワークの同一性** — 参照しているネットワークが、意図したチェーンであるか（generationHashなどによる確認）。

## BEYONDが依存するもの

一方で、BEYONDの検証は次の要素に依存します。ここが崩れると、検証結果の意味も変わります。

### ノードへの信頼

BEYONDは、チェーンのデータをノード（REST Node / Peer Node）から取得します。ノードが返す情報が正しいことを、BEYONDが単独で完全に保証することはできません。

この依存を緩和するために、BEYONDには次の考え方があります。

- **複数ノードの参照**：1つのノードだけを信頼せず、複数の情報源で突き合わせる。
- **Verified Node**：応答の整合性や健全性を確認したノードを区別して扱う。

### チェーンへの信頼

BEYONDは、参照先のブロックチェーンの合意形成が正しく機能していることを前提とします。チェーン自体が攻撃を受けている場合や、合意形成が機能していない場合、その上の記録の検証結果も影響を受けます。

チェーンの健全性そのものを作り出すことは、BEYONDの役割の外側にあります。

### ネットワーク設定への依存

検証は、「どのネットワークを見るか」という設定が正しいことに強く依存します。誤ったネットワーク設定（別のチェーン、別のテストネットなど）に接続していると、検証手順が正しく実行されても、意図と異なる対象を検証していることになります。

## Network Profile と Verified Node の考え方

この「ネットワーク設定への依存」を人間が扱える形にするのが、**Network Profile** です。

Network Profileは、generationHash・networkType・epochAdjustment・ノード一覧といった、ネットワークを特定するための情報をひとまとまりにしたものです。検証の前提となる「どのチェーンを、どのノード経由で見ているか」を明示し、確認可能にします。

その中で、応答の健全性を確認できたノードを **Verified Node** として扱うことで、「どの情報源に、どの程度依存しているか」を利用者が把握できるようにしています。

詳しくは [Network Profile](../guide/network-profile.md) をご覧ください。

## 検証手順を明示するという思想

BEYONDは「BEYONDが検証したから正しい」という受け取り方を推奨しません。

BEYONDが表示するのは、検証の**手順と根拠**です。どのデータを、どのノードから取得し、何と照合して、どう一致したか。この過程を人間が追えるようにすることが、BEYONDの役割です。

前提や限界も含めて公開する姿勢については、[BEYONDが保証すること / 保証しないこと](./guarantees.md) と [既知の制限](../reference/known-limitations.md) をあわせてご覧ください。

# 検証可能なデータとは

「データが残っている」と一口に言っても、その意味は一つではありません。このページでは、BEYONDが扱う「検証可能なデータ」という考え方を説明します。

## 保存・取得・検証は別のこと

次の3つは、それぞれ別の状態です。どれか1つが成り立っていても、他の2つが成り立つとは限りません。

1. **保存されていること** — どこかにデータが書き込まれた、という事実。
2. **取得できること** — 今、そのデータを実際に読み出せる、という状態。
3. **検証できること** — 取得したデータが、確かに記録された時のものであると、根拠をもって確認できる状態。

たとえば、あるサービスにファイルを保存したとします。保存された事実があっても、サービスが停止すれば取得できません。取得できても、それが改変されていないことを確認する手段がなければ、検証はできません。

BEYONDが焦点を当てるのは、この3つ目の「検証できること」です。

## ハッシュが残っていることと、データ実体があることは違う

ブロックチェーンには、データのハッシュ値（データから計算される固定長の値）だけを記録する方式がよく使われます。ハッシュ値は改ざん検知に有効ですが、それだけでは元のデータを復元できません。

- **ハッシュだけが残っている場合**：「このハッシュに一致するデータが、かつて存在した」ことは示せますが、データ実体が失われると、中身を確かめる手段がなくなります。
- **データ実体が残っている場合**：中身そのものを取得・確認できます。さらに記録時の情報と照合できれば、改ざんされていないことも確認できます。

どちらが優れているという話ではなく、「後から何を確認したいか」によって必要なものが変わる、という点が重要です。詳しくは [フルオンチェーンとは](./full-onchain.md) をご覧ください。

## データ実体と検証根拠の関係

検証可能なデータには、次の2つの要素が揃っている必要があります。

- **データ実体**：確認したい中身そのもの。
- **検証根拠**：そのデータが「いつ・どこに・どのように」記録されたかを示す情報。トランザクション、ブロック、ネットワーク情報などがこれにあたります。

データ実体だけがあっても、検証根拠がなければ「これは本物か」に答えられません。検証根拠だけがあっても、データ実体がなければ「中身は何か」に答えられません。両方が揃い、互いに照合できて初めて「検証可能」と言えます。

## BEYONDが見る検証ポイント

BEYONDは、おおまかに次のポイントを確認します。

1. **データ実体の確認** — 記録されたデータそのものが取得・復元できるか。
2. **ハッシュ・メタデータの照合** — 取得したデータが、記録時の情報と一致するか。
3. **トランザクションの確認** — その記録を作成したトランザクションが実在するか。誰が署名したか。
4. **ブロックの確認** — そのトランザクションがどのブロックに含まれているか。
5. **ネットワークの確認** — 参照しているチェーンとノードが、意図したものであるか。

具体的な手順は [データを検証する](../guide/verify-data.md) で説明しています。

## 非専門ユーザーの方へ

技術的な用語が多く登場しますが、考え方自体はシンプルです。

紙の証明書にたとえると、「証明書が発行された記録が台帳にある」（保存）、「証明書の原本が手元にある」（取得）、「原本と台帳を突き合わせて、内容と発行記録が一致すると確認できる」（検証）、という3段階に対応します。

BEYONDは、この「突き合わせ」の作業を、ブロックチェーン上の記録に対して、人間が理解できる形で行えるようにするプロダクトです。
